# Keeper Secrets Manager YubiKey Signer

Keeps the Keeper Secrets Manager client private key on a YubiKey. The key is generated by the YubiKey's
PIV application and never leaves the device; the SDK config holds no `privateKey`, and every request
is signed by the YubiKey.

Requirements:

- A YubiKey whose PIV application supports ECC P-256 (YubiKey 4 or 5). Other devices are rejected.
- Keeper Secrets Manager Java SDK `core` 17.5.0 or later.
- PC/SC: built into macOS and Windows, `pcscd` on Linux. The module talks to the YubiKey through the JDK's
  `javax.smartcardio`; no Yubico tools or native libraries are needed.

## Usage

Every KSM config needs its own key pair. `generateKey()` puts each new key in the first free retired slot,
and the config keeps the key's public key, which later locates the slot:

```kotlin
// Once, with a One-Time Access Token: generate the key on the YubiKey and bind its public key
YubiKeySigner(pin).use { signer ->
    initializeStorage(storage, "US:ONE_TIME_TOKEN", publicKey = signer.generateKey())
    val secrets = getSecrets(SecretsManagerOptions(storage, signer = signer, appKeyProtector = signer))
}

// Later runs: find the slot holding this config's key
YubiKeySigner.forPublicKey(pin, storage.getBytes(KEY_PUBLIC_KEY)!!).use { signer ->
    val secrets = getSecrets(SecretsManagerOptions(storage, signer = signer, appKeyProtector = signer))
}
```

Java:

```java
try (YubiKeySigner signer = new YubiKeySigner(pin)) {
    SecretsManager.initializeStorage(storage, "US:ONE_TIME_TOKEN", null, signer.generateKey());
    KeeperSecrets secrets = SecretsManager.getSecrets(SecretsManagerOptions.withSigner(storage, signer, signer));
}
try (YubiKeySigner signer = YubiKeySigner.forPublicKey(pin, storage.getBytes(SecretsManager.KEY_PUBLIC_KEY))) {
    KeeperSecrets secrets = SecretsManager.getSecrets(SecretsManagerOptions.withSigner(storage, signer, signer));
}
```

### App key wrapping

Passing the signer as `appKeyProtector` keeps the app key in the config only wrapped (`appKeyWrapped`):

- **Wrapping key:** one P-256 key-agreement key per YubiKey, shared by all configs. It lives in slot 9D, or in a free
  retired slot when 9D already holds something else. A certificate named `Keeper Secrets Manager App Key Wrapping`
  marks it. `generateKey()` creates it when missing.
- **Format:** ECIES. It holds the wrapping public key, an ephemeral public key, and the AES-256-GCM encrypted app
  key, with the AES key derived as SHA-256 of the ECDH secret. Wrapping needs neither PIN nor management key.
- **Unwrapping:** ECDH runs on the YubiKey and needs the PIN once per signer (none for PIN-less configs, see
  [Unattended use](#unattended-use)). The app key is then kept in memory
  until `close()`.
- **Failures:** if wrapping fails at binding (for example firmware older than 5.3), the SDK keeps the plain app key
  and logs a warning rather than lose it.

### Unattended use

KSM often runs where nobody can type the PIN: services, CI, cron. The PIV PIN policy of a key is fixed when the key
is generated, so there are two ways to run unattended.

**PIN-less keys**, for configs that are always unattended. Generate the key with `PinPolicy.NEVER` and open the signer
without a PIN:

```kotlin
YubiKeySigner().use { signer ->
    initializeStorage(storage, "US:ONE_TIME_TOKEN", publicKey = signer.generateKey(pinPolicy = PinPolicy.NEVER))
    getSecrets(SecretsManagerOptions(storage, signer = signer, appKeyProtector = signer))
}
YubiKeySigner.forPublicKey(storage.getBytes(KEY_PUBLIC_KEY)!!).use { signer -> /* ... */ }
```

- **Wrapping key:** the app key of a PIN-less config is wrapped by a second, PIN-less wrapping key. Its certificate is
  named `Keeper Secrets Manager App Key Wrapping, no PIN`, and `generateKey` creates it when missing. App keys of
  configs with a PIN-protected key are never wrapped by it.
- **Generation:** still needs the management key, but no PIN.
- **Touch policy:** keep it `NEVER` (the default for retired slots). A touch needs a person too.
- **Security:** the YubiKey alone is the factor. Anyone who can run code on the host with the YubiKey plugged in
  can use the key. With the PIN stored on that host, they could too, so the PIN-less key gives up little and
  leaves no secret on the host. A stolen config is still useless without the YubiKey.

**PIN saved in the config**, to leave a PIN-protected config unattended for a while:

```kotlin
// Attended, once: verify the PIN on the YubiKey and save it as privateKeyPin
YubiKeySigner.forPublicKey(PinProvider { readPin() }, publicKey).use { it.savePin(storage) }
// Every run: the PIN from the config, or a prompt when there is none
YubiKeySigner.forPublicKey(PinProvider.fromStorage(storage) { readPin() }, publicKey).use { signer -> /* ... */ }
// Attended again
YubiKeySigner.removePin(storage)
```

- **Lazy PIN:** a `PinProvider` is asked for the PIN only when the YubiKey requires it, and at most once per
  signer. The same code therefore serves PIN-less and PIN-protected keys.
- **Wrong PIN:** `savePin` never saves one. If the PIN saved in the config is wrong (e.g. the PIN was changed),
  each run fails with `The PIN saved in the config (privateKeyPin) is wrong` and does not fall back to the prompt.
  Once only one PIN retry is left, the signer stops using the saved PIN, so unattended runs cannot block the PIN.
- **Security:** the PIN is saved in plain text. The config plus the YubiKey then give full access, so protect the
  config file and remove the PIN when it is no longer needed.

### Key names

PIV keys have no names; tools show the subject of the slot's certificate instead. At binding the SDK calls
`onBound`, and the signer writes a self-signed certificate named after the KSM application title into the config's
slot. It is signed by the slot's own key, using the management key that was passed to `generateKey()`. macOS may then
list the key in Keychain Access, and may offer to pair the smart card.

### Options

- **Slot:** `YubiKeySigner(pin, slot, readerName)`. With no slot, `generateKey()` uses the first retired slot
  (`RETIRED1`–`RETIRED20`, 82–95) that holds neither a key nor a certificate. This leaves the standard slots
  (9A, 9C, 9D, 9E) free for smart card login and similar uses. Picking a free slot and `forPublicKey` both
  need firmware 5.3 or later; on older YubiKeys, pass the slot explicitly. The default PIN policy verifies the
  PIN once per connection; `PivSlot.SIGNATURE` (9C) asks for it on every request.
- **Reader:** with no `readerName` the first connected YubiKey is used. `YubiKeySigner.listYubiKeys()` lists
  the connected ones.
- **Management key:** `generateKey(managementKey, pinPolicy, touchPolicy, overwrite)`.
  - The management key defaults to the factory default key. 3DES and AES (firmware 5.4+) management keys
    are supported.
  - `TouchPolicy.ALWAYS` makes every request wait for a touch.
  - `generateKey` refuses to replace a key or certificate already in the slot unless `overwrite = true`.
- **Key location:** `signer.keyLocation`, e.g. `"YubiKey 5C NFC FIPS, serial 12345678, PIV slot 82 (RETIRED1)"`, tells people
  which YubiKey holds a config's key. The model is the name ykman shows, and the serial is printed on the YubiKey. The SDK saves it in the config as
  `privateKeyLocation` on every request made with the signer, if it is missing or has changed. A PIN-less key
  ([Unattended use](#unattended-use)) adds `, unattended (no PIN)`. A PIN saved in the config shows as `privateKeyPin`
  instead. It is informational only: `forPublicKey` finds the slot by public key.
- **Public key:** `signer.publicKey` reads the slot's public key back (firmware 5.3+). Unlike a software key,
  core keeps `publicKey` in the config after binding when the private key is external.

The signer keeps one connection to the YubiKey open and, once it has the PIN, holds a copy of it in memory, so it can
re-verify the PIN when another application resets the card. `close()` wipes the PIN and resets the card.

On JDK 8 on recent macOS versions, `javax.smartcardio` may fail to find the PC/SC framework. Run with
`-Dsun.security.smartcardio.library=/System/Library/Frameworks/PCSC.framework/Versions/Current/PCSC`.
